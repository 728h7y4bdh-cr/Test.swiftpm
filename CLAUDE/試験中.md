# 試験中.md

このファイルは、`docs/Test specification/BlueCom設計検査仕様書.md`（以下「試験仕様書」）に基づく試験を、実際に開始してから終了・完了するまでの間にCLAUDEが参照する運用ルールである。

本ファイルは**試験実施フェーズ**でのみ参照する。試験仕様書そのものの作成・修正フェーズでは、代わりに`CLAUDE/設計検査仕様書作成.md`を参照する（両方を常時参照する運用にはしない。詳細はCLAUDE.mdの参照ルールを参照）。試験仕様書の構成・試験項目の設計方法・判定基準の文章作成方法等、作成フェーズだけに必要なルールは本ファイルには記載しない。

不要な一般論は記載せず、CLAUDEが試験中に誤った記録・更新を行わないために必要なルールに限定する。

## 1. 試験結果の記録

- 試験結果（4章各項目の「試験結果」表）には、実際に得られた情報だけを記録する。実施日・バージョン・結果・判定・担当者は、ユーザーから伝えられた内容以外を推測して記入しない。
- 「結果」欄には、試験を実施して実際に確認された事実・状態そのものを記録する（例：「60秒後に『該当する端末がありませんでした』が表示された」）。CLAUDEが「起きたはずのこと」を推測して書かない。
- 「判定」欄（OK／NG／未実施／保留）は、ユーザーが決定した内容をそのまま反映する。CLAUDEが結果の内容から独自に判定を導いて設定しない。「未実施」「保留」とするかどうかも同様にユーザー判断であり、CLAUDEが勝手に設定しない。
- 再試験を行った場合も同様に、実際に得られた結果・判定のみを記録する。再試験前の記録を削除する場合は、ユーザーの指示を確認してから行う。
- 試験結果は、ユーザーがチェックリスト等を用いてまとめて報告してよい。「OK」は、記載された試験手順を実施し判定基準をすべて満たしたことをユーザーが確認した結果として、「NG」はユーザーが記録した観測事実（実測値の併記があればその値も含む）として、それぞれ本節の原則に従い反映する。
- 報告内容に意味不明・情報不足・記載どおり反映すると事実と異なるおそれがある等の問題がある場合、その項目は反映せず、該当する試験番号と内容をユーザーへ報告し、確認を得てから反映する。
- 試験結果に、試験手順・判定基準・試験項目そのものの不足や変更を示す記載が含まれている場合、その内容をCLAUDEの判断で正式な試験仕様書（3章・4章の試験手順・判定基準・試験項目）へ反映しない。反映は、ユーザーから具体的な修正指示が与えられた場合にのみ行う。

## 2. 問題点一覧表（5章）への反映

- 試験結果の判定がNGの場合、ユーザーから個別に「問題点一覧へ登録して」等の指示がなくても、問題点一覧への登録を行う。
- 問題番号は1・2・3…の単純な連番で採番する。
- 問題を記録する場合は、「関連試験番号」に該当する試験番号を記載し、試験結果との追跡関係を維持する。1件の問題が複数の試験に関連する場合は、複数の試験番号をカンマ区切りで記載する。
- 内容・原因・対策・対処日・再試験の記録は、ユーザーから伝えられた情報のみを記載する。CLAUDEが原因や対策を推測して書かない。

## 3. 1章「総合結果・判定」の更新

- 1.3節の結果集計、1.1節の総合判定は、CLAUDEが自発的に更新しない。ユーザーから集計・更新の指示があったときに、3章の試験項目表・4章の各試験結果を基に更新する。
- 更新の際は、結果集計の合計件数が3章の試験項目数と一致しているか確認する。
- 総合判定（合格／不合格）をCLAUDEが独自判断で確定しない。NG件数や未実施・保留の扱いも含め、ユーザーの判断を反映する。

## 4. 試験仕様書本文への追記禁止事項

- 上記1〜3の運用（誰が・いつ・どのように記録・更新するか）についての説明を、試験仕様書本文（`BlueCom設計検査仕様書.md`）へ追記しない。運用ルールは本ファイルにのみ記載する。

## 5. NG発生時の試験運用

- NGが発生しただけで機械的に全試験を中断しない。以下の流れで対応する。
  1. 問題点一覧へ登録する。
  2. 後続試験への影響を確認する。
  3. 影響しない場合は試験を継続し、原則として一通りの試験完了後に原因調査・対策・再試験を行う。
  4. 影響する場合は、必要な時点で原因調査・対策・再試験を行い、後続試験を継続できる状態にしてから再開する。
- 後続試験への影響有無は、根拠なく推測で決定しない。判断が難しい場合はユーザーへ確認する。
