# 試験中用.md

このファイルは、`BlueCom設計検査仕様書.md`（以下「試験仕様書」）が完成した後、実際に試験を実施して結果を記録・更新するときにCLAUDEが必ず参照する運用ルールである。試験仕様書の作成・修正そのものに関するルールは`試験仕様書作成用.md`を参照すること。

不要な一般論は記載せず、CLAUDEが試験中に誤った更新を行わないために必要なルールに限定する。

## 1. 試験結果の記録

- 試験結果（8章各項目の「試験結果」表）には、実際に得られた情報だけを記録する。実施日・バージョン・結果・判定・担当者は、ユーザーから伝えられた内容以外を推測して記入しない。
- 「結果」欄には、試験を実施して実際に確認された事実・状態そのものを記録する（例：「60秒後に『該当する端末がありませんでした』が表示された」）。CLAUDEが「起きたはずのこと」を推測して書かない。
- 「判定」欄（OK／NG／未実施／保留）は、ユーザーが決定した内容をそのまま反映する。CLAUDEが結果の内容から独自に判定を導いて設定しない。「未実施」「保留」も同様にユーザー判断であり、CLAUDEが勝手に設定しない。

## 2. 問題点一覧表（9章）

- 問題を記録する場合は、「関連試験番号」に該当する試験番号を記載し、試験結果との追跡関係を維持する。
- 登録・原因・対策・再試験の内容は、ユーザーから伝えられた情報のみを記載する。

## 3. 5章「総合結果・判定」の更新

- 5.3節の結果集計、5.1節の総合判定は、CLAUDEが自発的に更新しない。ユーザーから集計・更新の指示があったときに、7章の試験項目表・8章の各試験結果を基に更新する。
- 更新の際は、結果集計の合計件数が7章の試験項目数と一致しているか確認する。
- 総合判定（合格／不合格）をCLAUDEが独自判断で確定しない。NG件数や未実施・保留の扱いも含め、ユーザーの判断を反映する。

## 4. 試験仕様書本文への追記禁止事項

- 上記の運用（誰が・いつ・どのように更新するか）についての説明を、試験仕様書本文（`BlueCom設計検査仕様書.md`）へ追記しない。運用ルールは本ファイルにのみ記載する。
