# BlueCom 試験失敗報告書

## 発覚日

2026年9月29日

試験継続不可と判断した日


## 試験失敗の概要

BlueCom設計検査仕様書に基づく実機試験において、設計と異なる期待結果、試験者が確認できない判定基準、判定に必要な操作手順の不足等が複数確認された。

実施済み16件のうち8件で、試験直前または試験中に試験仕様の修正が必要となった。さらに、未実施27件を確認した結果、15件に不備が確認された。

この結果、全43件中23件で試験仕様に不備が確認された。

原因調査の結果、試験仕様書作成時の設計照合および、その後のレビューにおける設計との整合性、試験の実施・判定可能性の確認が不十分であったことが判明した。

以上から、現行の試験仕様書による試験継続は不可と判断した。


## 詳細

### 現象

全43件の試験のうち16件を実施した時点で、8件について試験仕様の修正が必要となった。

試験継続の可否を判断するため、未実施の27件についても試験内容を確認した結果、15件に不備が確認された。

実施済み・未実施を合わせると、全43件中23件で試験仕様に不備が確認された。


#### 実施済み試験で判明した不備

実施済み16件のうち、以下の8件で試験直前または試験中に試験仕様の修正が必要となった。

**CONN-04**

自端末ID欄の数値キーボード表示のみを確認する手順となっており、同じ仕様が適用される接続先ID欄を確認する手順が不足していた。

接続先ID欄についても実際にタップして数値キーボードが表示されることを確認する手順・判定基準を追加した。

**CONN-05**

自端末ID欄についてのみ4桁目を入力できないことを確認する手順となっており、接続先ID欄の入力桁数制限を確認する手順が不足していた。

接続先ID欄についても4桁以上の入力を行い、3桁までに制限されることを確認する手順・判定基準を追加した。

**CONN-07**

「Bluetooth通信開始処理が実行されないこと」「待受開始処理が実行されないこと」という、画面表示や操作結果から直接確認できない内部処理を判定対象としていた。

試験者が確認可能なダイアログ表示および画面遷移の有無によって判定する内容へ修正した。

**HS-04**

試験手順に「Bluetooth通信切断処理が完了するまで待つ」と記載されていたが、試験者には内部の切断処理完了を直接確認する手段がなかった。

内部処理の完了を試験者に判断させる手順を削除し、画面表示および実際の操作結果によって状態を確認する内容へ修正した。

**HS-05**

HS-04と同様に、「Bluetooth通信切断処理が完了するまで待つ」という、試験者が直接確認できない内部状態を前提とした手順となっていた。

内部処理の完了を試験者に判断させず、画面表示および実際の操作結果によって状態を確認する内容へ修正した。

**GUARD-01**

Core Bluetooth側の切断完了前であることや、通信開始処理・待受開始処理が開始されていないこと等、試験者が直接確認できない内部状態・内部処理を試験目的・試験手順・判定基準としていた。

「しばらくしてから操作してください」の表示、「接続中」が表示されないこと、画面遷移しないこと、その後再び通信操作を開始できること等、画面と操作結果から判定できる内容へ修正した。

**GUARD-02**

試験目的の記載が設計書の記載に依存しており、試験単独で確認目的を把握できない状態だった。

また、接続成立を確認するための相手端末側の操作手順が不足しており、記載された手順だけでは判定基準を確認できなかった。

試験目的を単独で理解できる内容へ修正し、相手端末をBluetooth接続画面へ戻してから接続操作を行う手順を追加した。

**GUARD-03**

GUARD-02と同様に、試験目的が他の記載に依存しており、試験単独で確認目的を把握できない状態だった。

また、接続成立を確認するための相手端末側の操作手順が不足しており、記載された手順だけでは判定基準を確認できなかった。

試験目的を単独で理解できる内容へ修正し、相手端末をBluetooth接続画面へ戻してから待受操作を行う手順を追加した。


#### 未実施試験の確認で判明した不備

未実施27件について確認した結果、以下の15件に不備が確認された。

**SEND-01**

設計では「データ送信完了」ダイアログをOK操作で閉じる仕様であるにもかかわらず、試験仕様書では「その後自動的に閉じて」と、設計に存在しない動作を判定基準としていた。

また、受信側の「データ受信完了」ダイアログを閉じる操作がないまま「受信再開」操作へ進む手順となっていた。

**SEND-02**

送信応答が返らない状態を作る方法が試験条件として確定されておらず、例示された操作では予期しない切断等、試験対象とは別の動作が発生する可能性があった。

記載された条件では、意図した異常状態を一意に再現できない。

**SEND-03**

SEND-03では、受信側が「受信再開」を行わない状態で再送すると応答が返らず、設計上、送信側は10秒のタイムアウト後にBluetooth通信切断処理を実行して異常終了する。この切断を受信側が検出すると「Bluetooth通信が切断されました。再接続してください」を表示する仕様であるにもかかわらず、試験仕様書では「端末B側の表示は変化しないこと」を判定基準としており、設計と矛盾していた。

**SEND-04**

「データ送信中」表示中に「戻る」をタップする手順となっているが、表示中のダイアログによって背面画面を操作できないため、記載された操作を実施できない。

**SEND-05**

送信完了後のダイアログを閉じる操作が手順に含まれていないまま、次の送信操作へ進む手順となっていた。

そのため、記載された手順のまま5回連続の送信操作を実施できない。

**RECV-02**

「受信処理が継続していること」を判定対象としているが、受信処理の継続は画面から直接確認できず、後続データを実際に受信する等の確認手順もなかった。

**RECV-03**

試験目的が「RECV-02と同じダイアログ」と他試験を参照する記載になっており、当該試験だけでは確認対象が完結していなかった。

**RECV-06**

画面やボタンが操作可能な状態であることを判定対象としているが、実際に入力やボタン操作を行って確認する手順が不足していた。

**DISC-01**

試験手順では送信処理中の状態を作っていないにもかかわらず、「進行中の送信処理があれば中断されること」を判定対象としていた。

また、内部の送信処理が中断されたこと自体を画面から直接確認することもできない。

**DISC-02**

切断通知後の画面遷移を判定対象としているが、その遷移に必要なダイアログのOK操作が試験手順に記載されていなかった。

**ORDER-02**

操作後に入力欄・ボタンが操作可能な状態であることを判定対象としているが、実際に入力またはボタン操作を行って確認する手順がなかった。

**ORDER-03**

操作後に入力欄・ボタンが操作可能な状態であることを判定対象としているが、実際に入力またはボタン操作を行って確認する手順がなかった。

**ORDER-04**

操作後に入力欄・ボタンが操作可能な状態であることを判定対象としているが、実際に入力またはボタン操作を行って確認する手順がなかった。

**E2E-01**

一連の通信操作の終了後に入力欄・ボタンが操作可能な状態であることを判定対象としているが、実際に入力またはボタン操作を行って確認する手順がなかった。

**E2E-02**

E2E-01と同様に、一連の通信操作の終了後に入力欄・ボタンが操作可能な状態であることを判定対象としているが、実際に入力またはボタン操作を行って確認する手順がなかった。


### 原因

#### 試験仕様書作成時の設計照合不足

設計内容を試験仕様へ展開する際の照合が不十分であり、設計根拠のない内容や、設計と一致しない内容が試験仕様に含まれた。

SEND-01では、設計書に「データ送信完了」ダイアログをOK操作で閉じることが明記されていたにもかかわらず、設計に存在しない「自動的に閉じる」という動作が試験仕様書の初版から記載されていた。


#### 試験実施可能性の確認不足

試験手順を実際の画面操作として成立させられるか、また、判定基準を試験者が実際に確認できるかという観点での確認が不十分だった。

そのため、必要な操作が不足している試験、画面上実施できない操作を要求する試験、内部処理を直接判定しようとする試験が作成された。


#### レビュー方法の不足

複数回のレビューを実施したが、表現や記載形式の確認が中心となり、設計内容と試験内容を意味的に照合するレビューが不足していた。

そのため、設計と異なる内容や、試験者が実際には実施・判定できない内容を検出できなかった。


#### AIの役割遂行上の問題

Claudeによる試験仕様書の作成・自己レビュー、およびChatGPTによるレビュー・成果物確認のいずれでも、設計との不整合や試験実施上の問題を十分に検出できなかった。

設計との整合性および試験の実施・判定可能性を確認するという、各AIに与えられた役割上必要な品質確認が不十分であった。


## 対応策

試験工程および試験仕様書を1から再構築する。
